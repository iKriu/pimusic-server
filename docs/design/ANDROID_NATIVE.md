# PiMusic для Android — нативный клиент

Нативное приложение: интерфейс — в APK (Kotlin + Jetpack Compose, Material 3 Expressive по `DESIGN.md`), с сервера
берутся только API (`PLAYER_API.md`, `APPS_API.md`) и потоки. `applicationId` `io.github.ikriu.pimusic`; версия —
`versionName`/`versionCode` в `apps/android-native/app/build.gradle.kts` (`versionCode` = major·10000 + minor·100 +
patch). Каталог: `apps/android-native/`, сборка — `apps/build/build-android-native.sh`.

## Архитектура
Один Gradle-модуль `app`, слои — пакеты (зависимости только сверху вниз):

| Пакет | Что внутри |
|---|---|
| `core` | чистая логика без Android: очередь (`QueueModel`), разбор чисел EQ, биквады/АЧХ (`Biquad`), нормализация, LAN-правило адреса, проверка манифеста обновлений, слияние настроек (`SettingsMerge`), цвет M3 (`M3Color` — порт `static/js/color.js`) — всё покрыто JVM-тестами |
| `data` | `Api` (OkHttp + kotlinx.serialization, `Authorization: Bearer`), DTO (`Models.kt`), `ApiCache` (ответы GET на диске → мгновенное открытие, затем обновление), `Session` (сервер, токен, логин, id устройства), `SettingsStore` (ключи `/api/settings` с `base`/409 — как `settings.js`), `Repo` |
| `player` | `PlayerHub` (ExoPlayer + очередь + опции), `PlaybackService` (MediaSessionService: фон, уведомление, гарнитура/Bluetooth), `MediaCaches` (кэш потока и скачанное), `Prefetcher`, `OfflineDownloads` + `DownloadsService`, `EqAudioProcessor`, `SleepTimer` |
| `update` | автообновление (`android.json`, sha256, PackageInstaller) с M3-диалогом Compose |
| `ui` | тема (`PiTheme`: seed #F5A524 / акцент / цвет обложки, светлая/тёмная/системная, `MotionScheme.expressive()`), навигация (свой стек экранов в `AppState`), экраны и компоненты |

Состояние экранов — `StateFlow` в `AppState`/`PlayerHub`; навигация — стек `Screen` (без navigation-compose:
меньше зависимостей, «Назад» — `BackHandler`). Раскладка по window size class: compact — navigation bar снизу,
medium+ — navigation rail; «Сейчас играет» — полноэкранный лист (compact) или панель справа (expanded).

## Экраны
Вход (код подтверждения + «Войти через Telegram», опрос `/api/auth/poll` каждые 2 с, смена сервера) · Поиск
(каталог: исполнитель/треки/альбомы, «Скачать», ссылка Spotify/YouTube/… → `/api/download/link`, ✓ по
`/api/library/keys`) · Альбом/исполнитель каталога · Медиатека (Треки · Исполнители · Альбомы · Плейлисты, поиск,
сортировки и жанры как `libsort.js`, «Слушать»/«Перемешать») · Свой исполнитель/альбом · Плейлист (свои/общие,
правка: перестановка/удаление, переименование, поделиться, сохранить в медиатеку, скачать офлайн, удалить/выйти) ·
Загрузки (активность, импорты с паузой/отменой, свои файлы: выбор аудио и TXT/CSV, `need_info`) · Моя Волна
(эфир, «Обновить плейлист», «Найти новое») · Сейчас играет (обложка с цветом, волнистая перемотка, shuffle/repeat,
текст `.lrc` синхронно, очередь с перетаскиванием, эквалайзер, таймер сна, скорость) · Мини-плеер (смахивание
влево/вправо — следующий/предыдущий) · Скачанное (размер, удаление, всё офлайн) · Настройки (тема и акцент,
воспроизведение, кэш, офлайн-режим, устройства, выход, сервер, обновления).
Кнопка «к текущему треку» — на списках медиатеки и плейлиста. Telegram — только вход.

## Кэш и скачивание
* **Кэш потока** — Media3 `SimpleCache` в `cacheDir/media`, свой LRU-вытеснитель с лимитом из настроек
  (по умолчанию 2 ГБ, 256 МБ…16 ГБ, меняется без перезапуска). Ключ кэша — `track:<id>` (подписанная ссылка
  меняется каждый час, ключ — нет). `Prefetcher` (Media3 `CacheWriter`) докачивает **целиком** текущий и 2 следующих
  трека очереди (не трогая скачанные), только при наличии сети; ExoPlayer буферизует до 10 мин вперёд.
* **Скачанное** — отдельный `SimpleCache` в `filesDir/offline` с `NoOpCacheEvictor` (не вытесняется),
  `DownloadManager` + `DownloadsService` (уведомление с прогрессом, «только Wi-Fi» — настройка). В
  `DownloadRequest.data` — JSON трека (офлайн-метаданные). Удаляется только пользователем.
* **Воспроизведение**: `CacheDataSource`(скачанное, только чтение) → `CacheDataSource`(кэш потока) → OkHttp.
  Волна (живой поток) идёт мимо кэша. Ссылка истекла/404 — свежие ссылки `GET /api/tracks?ids=` и повтор.
* **Офлайн-режим** (переключатель или нет сети): медиатека/плейлисты из `ApiCache`, играют скачанные и
  закэшированные треки; экран «Скачанное» работает без сервера.
* **Обложки** — Coil 3: память + диск 300 МБ, ключ — путь `/api/cover/<id>` без подписи. **Ответы API** —
  `ApiCache` (файлы JSON в `cacheDir/api`): экран сразу показывает прошлый ответ, затем свежий.

## Звук
`EqAudioProcessor` (Media3 `AudioProcessor`, PCM 16 бит/float) — те же параметры, что веб: 10 полос
(частота 20–20000, усиление ±12 дБ, Q 0,3–8, крайние — пик/полка), преамп −12…+6, лимитер, A/B; формулы биквадов —
RBJ Audio EQ Cookbook (как `BiquadFilterNode`). Профили и синхронизация — ключи `eq.presets`, `eq.shared`,
`eq.device.<uuid>` (формат `eq.js`). Нормализация — по `gain`/`peak` (подъём ≤ +6 дБ и не выше пика), усиление
внутри процессора перед лимитером. `android.media.audiofx` не используется: у системного `Equalizer` фиксированные
полосы без Q, а `DynamicsProcessing` не даёт пиковых фильтров — совпадения с вебом не получить. Скорость — Sonic
(`PlaybackParameters`, высота сохраняется). Таймер сна — затухание 8 с громкостью плеера.
**Плавный переход** (2.0.1, ключ `player.crossfade` 0–12 с, как Mini App): за N с до конца второй ExoPlayer («хвост», без
аудиофокуса и без MediaSession, свой экземпляр EQ с нормализацией уходящего трека) доигрывает конец, а главный плеер
(его видит MediaSession — уведомление и гарнитура сразу показывают следующий трек) переходит дальше; громкости — равная
мощность (cos/sin). Не включается: волна, «повтор трека», таймер «до конца трека», трек короче 2,5× перехода; пауза или
перемотка во время перехода гасит хвост. 0 — без паузы (gapless). Таймер сна умножается на громкости перехода.
**Спектр** (2.0.1) поверх кривой EQ: на выходе процессора кольцевой буфер, БПФ 2048 с окном Блэкмана и сглаживанием 0,8
(как AnalyserNode) — только пока открыт экран эквалайзера, включён «Спектр» (`eq.device.<id>.spectrum`) и нет
«уменьшения движения».

## Соответствие API
| Функция | Эндпоинты |
|---|---|
| вход/выход | `POST /api/auth/start` `{device, platform:"android"}`, `/auth/poll`, `/auth/logout` (`all`), `GET /api/devices`, `/devices/{id}/revoke` |
| профиль | `GET /api/me` (`login`, `tracks`, `stream_url` волны) |
| медиатека | `/api/library` (`q, genre, sort, order, offset, limit`), `/library/genres`, `/library/artists`, `/library/albums`, `/library/artist?a=`, `/library/album?a=&b=`, `/library/play`, `/library/keys`, `/library/delete`, `/api/delete` |
| плеер | `/api/stream/{id}` (Range), `/api/cover/{id}`, `/api/tracks?ids=`, `/api/lyrics/{id}` |
| плейлисты | весь раздел `PLAYER_API.md` + `move-many`, `remove` пачкой |
| поиск/скачать | `/api/search`, `/api/album`, `/api/catalog/{album,artist,artist/tracks}`, `/api/download`, `/api/download/link`, `/api/activity` |
| файлы/импорт | `/api/upload` (multipart, прогресс), `/api/uploads`, `/uploads/{id}/{info,skip,cancel}`, `/api/import/file`, `/api/import`, `/import/{pause,resume,cancel}` |
| волна | `/api/wave/now`, `/wave/refresh`, `/wave/discover`, поток `stream_url` |
| настройки | `GET /api/settings`, `PUT/DELETE /api/settings/<key>` (ключи `ui.theme`, `player`, `eq.*`) |
| обновления | `android.json` последнего выпуска GitHub → APK (только из выпусков репозитория, см. `APPS_API.md`) |

## 2.0.1
* Плавный переход и спектр (см. «Звук»).
* Режим выбора (медиатека, свои альбом/исполнитель, плейлист): кнопка «Выбрать» → шапка «Выбрано: N · Выбрать все»,
  плавающая панель M3E: «Следующими», «В очередь», «В плейлист», «На устройство» (оценка по `size`), «Удалить»
  (`/api/library/delete` пачками по 500, с подтверждением); в плейлисте — «Убрать», «В начало», «В конец» (`move-many`,
  только в «Порядке плейлиста»). «Назад» снимает выбор.
* Новые поля API: `artist_key`/`album_key` — «К исполнителю/К альбому» сразу по ключам; у чужого трека (`owned: false`)
  пункты скрыты. `size` — «≈ N МБ» в «Скачать на устройство». `/api/wave/now.track_id` — PlayerHub опрашивает эфир, пока
  играет Волна, и обновляет метаданные уведомления (название, исполнитель, обложка) `replaceMediaItem` без перезапуска
  потока. `/api/activity.active_items` — ход загрузок в поиске («Качается · Soulseek: …»), ключи медиатеки перечитываются
  только когда загрузка закончилась.
* Широкие экраны: обложки очереди — карусель (смахивание — соседний трек без смены play/pause), в панели — «Далее»
  (5 следующих); на ≥ 1200dp панель «Сейчас играет» закреплена и открывается сама при старте очереди, пока её не
  закрыли; на ≥ 1600dp — 480dp.
* Тесты: `SettingsStore` вынесен от Android (интерфейсы `Storage`/`Backend`) — JVM-тесты конфликтов/парковки/синхронизации;
  UI-тесты Compose под Robolectric (SDK 34, офлайн: образ `android-all-instrumented` скачивает Gradle с проверкой sha256).
  Тесты идут на debug-варианте (`testDebugUnitTest`), APK — release.

## 2.0.2
* **Вёрстка M3E по скриншотам.** Переключатель видов — connected button group из material3 (`ToggleButton` +
  `ButtonGroupDefaults.connected*ButtonShapes`: внешние углы скруглены, внутренние малые, выбранный морфит в пилюлю), на
  всю ширину с равными весами; подписи не исчезают: не помещаются с иконкой в строку — иконка над подписью, общий кегль
  для всех кнопок (до 70 %), затем короткая подпись («Артисты»); TalkBack читает полную. «Слушать/Перемешать» — medium
  56dp на всю ширину; тесно (крупный шрифт + доп. действия) — «Перемешать» становится тональной кнопкой-иконкой.
  Строка «N треков · сортировка · выбрать» — 48dp, по центру, чип сортировки с короткой подписью (полная — для
  TalkBack). Подписи вкладок, плиток плеера, кнопок — `FitText` (ужимается, без переноса по буквам). Очередь: «Выше/Ниже»
  — действия TalkBack, видимой осталась только ✕. Полосы EQ — прокручиваемый ряд чипов.
* **Скриншот-тесты** (Roborazzi на Robolectric, без эмулятора): 32 экрана/состояния × 360×800, 800×360, 1280×800 ×
  светлая/тёмная × fontScale 1.0/1.3, поддельный сервер `FakeServer` (ответы API и обложки-градиенты).
  `SCREENSHOTS=1 build-android-native.sh` → `<каталог сборки>/out/android-native/shots/<конфигурация>/*.png`.
* **Жесты плеера:** свайп вверх по мини-плееру выдвигает «Сейчас играет» (лист следует за пальцем), свайп вниз по шапке
  или по прокрутке, упёршейся в верх, — сворачивает; отпускание — пружина M3E по положению и скорости
  (`PlayerSheet`). Ось жеста мини-плеера выбирается по первому движению: по горизонтали — следующий/предыдущий.
* **«Играет из …»** над обложкой и в очереди (плейлист, альбом, исполнитель, медиатека, скачанное, Волна): `PlaySource`
  сохраняется с очередью; тап — переход к источнику. В метаданных MediaSession — подзаголовок «Играет из «…»».
* **В несколько плейлистов сразу:** лист с чекбоксами (TriState для выделения), «Готово» применяет всё разом —
  добавить в отмеченные, убрать из снятых (`/api/playlists/for-track` + `add`/`remove`).
* **Очередь батчем:** массовые изменения (обновление ссылок, удаление недоступных, перемешивание) — не больше двух
  изменений таймлайна (`replaceQueue`); тест на 2000 треков. Системной сессии очередь не отдаётся (OneUI).
* **Live Updates (Android 16):** скачивание на устройство и загрузка обновления APK — `NotificationCompat.ProgressStyle`
  + `setRequestPromotedOngoing` + `setShortCriticalText` («3/12», «45%»), ongoing, без colorized/custom view, канал LOW;
  `canPostPromotedNotifications()` запрещает — обычное уведомление с прогрессом; обновления не чаще раза в секунду.
  Разрешение `POST_PROMOTED_NOTIFICATIONS`. Плеер — без Live Update (MediaStyle исключены), обложка для системной
  сессии ограничена 512 px (`DataSourceBitmapLoader.setMaximumOutputDimension`), у Волны — трек эфира с обложкой.
* **Текст песни:** «Найти текст заново» (`POST /api/tracks/{id}/lyrics/refetch`, до 100 с) и «Убрать текст» (своя
  медиатека, `clear`), снекбар по `status` (updated/same/cleared/not_found) и ошибкам 409/429/504.

## План
1. Каркас Gradle (wrapper 8.14.3 с sha256, AGP 8.13, Kotlin 2.3, версии в `gradle/libs.versions.toml`), тема, вход.
2. Данные: `Api`, DTO, `ApiCache`, `SettingsStore`; медиатека, поиск, плейлисты, загрузки, волна.
3. Плеер: `PlayerHub`, служба, кэши, предзагрузка, скачивание, EQ, таймер сна, текст.
4. Обновления, настройки, офлайн. 5. JVM-тесты логики, сборка в контейнере, `apksigner verify`.
