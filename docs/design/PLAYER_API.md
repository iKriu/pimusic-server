# Плеер по своим трекам + плейлисты — контракт (бэкенд ↔ Mini App)

Код: бот — `bot/app/*.py`, Mini App — `bot/app/static/`.
Дизайн-контракт Mini App: `design/DESIGN.md` (Material 3 Expressive, русский UI). Все строки UI — по-русски.

## Цели
1. В Mini App можно слушать **любые свои треки** (не только «Мою Волну»): очередь, next/prev, перемотка,
   shuffle, repeat (off / all / one), полноэкранный плеер, мини-плеер, Media Session (экран блокировки, гарнитура).
2. **Свои плейлисты**: создать, переименовать, описание, добавить/удалить/переставить треки, удалить плейлист.
3. **Общие (совместные) плейлисты**: владелец включает «общий доступ» → получает ссылку-приглашение;
   другой пользователь бота открывает ссылку → становится участником-редактором (может добавлять/удалять треки).
   Участник может выйти; владелец может убрать участника и выключить доступ (новая ссылка = старая перестаёт работать).
4. «Сохранить в медиатеку» — треки плейлиста, которых у пользователя нет, добавляются в его медиатеку
   хардлинком из общего кэша (без скачивания).

## Поток аудио
`<audio>` не шлёт заголовки → подписанная ссылка (как обложки).

`GET /api/stream/{track_id}?u=<login>&e=<unix-exp>&s=<sig>`
- `sig = HMAC(_cover_key(bot_token)-подобный отдельный ключ b"PiMusicStream", f"{login}:{track_id}:{exp}")[:32]`
- `exp` = текущее время + 12 ч, округлённое вверх до часа (стабильные URL → кэш браузера работает).
- Доступ: трек в медиатеке пользователя **или** трек входит в плейлист, где пользователь — участник.
- Ответ: `web.FileResponse` (поддержка Range/206 обязательна — перемотка), `Content-Type: audio/mpeg`,
  `Cache-Control: private, max-age=3600`. Нет доступа / плохая подпись / истекла → 404 (без подробностей).
- Файл: ссылка пользователя (`link_path`), а если её нет (трек из чужого общего плейлиста) — `tracks.path` в кэше.
- Обложка `/api/cover/{id}` — тот же расширенный доступ (сейчас только `user_has_track`).

## Сериализация трека (единая для медиатеки, альбомов, исполнителей, плейлистов)
Дополнить `_lib_item`:
```json
{"id": 12, "artist": "Кино", "title": "Группа крови", "album": "Группа крови",
 "duration": "4:46", "seconds": 286, "cover": "/api/cover/12?...", "stream": "/api/stream/12?u=..&e=..&s=..",
 "owned": true}
```
`owned` — есть ли трек в медиатеке пользователя (в общих плейлистах может быть false).
В плейлистах дополнительно: `"item_id": 55, "added_by": "PasturTheFox"`.

## Свежие ссылки на треки
`GET /api/tracks?ids=1,2,3` (≤ 500) → `{"items":[трек…]}` в порядке запроса, недоступные пропущены.

## Очередь «вся медиатека»
`GET /api/library/play?order=shuffle|artist|recent&limit=1000` (limit ≤ 3000) →
`{"total": 1010, "items": [трек…]}` — для «Слушать всё» / «Перемешать всё».

## Плейлисты — БД (`db.py`, миграция через CREATE TABLE IF NOT EXISTS)
```sql
playlists(id INTEGER PK, owner TEXT NOT NULL REFERENCES users(login) ON DELETE CASCADE,
          name TEXT NOT NULL, description TEXT NOT NULL DEFAULT '',
          share_token TEXT UNIQUE,            -- NULL = личный; не NULL = общий, токен приглашения
          created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL)
playlist_members(playlist_id REFERENCES playlists ON DELETE CASCADE, login REFERENCES users ON DELETE CASCADE,
                 joined_at INTEGER NOT NULL, PRIMARY KEY(playlist_id, login))   -- владелец сюда НЕ пишется
playlist_items(id INTEGER PK, playlist_id REFERENCES playlists ON DELETE CASCADE,
               track_id REFERENCES tracks ON DELETE CASCADE, added_by TEXT, position REAL NOT NULL,
               added_at INTEGER NOT NULL, UNIQUE(playlist_id, track_id))
```
Ограничения: имя 1–100 символов (обрезать пробелы), описание ≤ 300, ≤ 200 плейлистов на пользователя,
≤ 5000 треков в плейлисте, ≤ 20 участников. Токен — `secrets.token_urlsafe(9)`.
Добавлять в плейлист можно только треки, к которым у добавляющего есть доступ (медиатека или этот же плейлист).
Удаление трека из медиатеки (`/api/delete`) НЕ удаляет его из плейлистов (файл в кэше остаётся, пока он
нужен плейлистам — проверить, что `delete_track` не удаляет файл кэша, если трек есть в каком-либо плейлисте).

## Плейлисты — API (всё под `self.api(...)`, ошибки через `_err(code, slug, message=...)`)
Плейлист (краткий):
```json
{"id": 3, "name": "Дорога", "description": "", "count": 42, "seconds": 9876,
 "covers": ["/api/cover/..", "..", "..", ".."],   // до 4 разных обложек для мозаики
 "shared": true, "role": "owner"|"member", "owner": "iKriu",
 "members": [{"login": "PasturTheFox"}], "updated_at": 1760000000}
```
| Метод | Путь | Тело / query | Ответ |
|---|---|---|---|
| GET | /api/playlists | — | `{"items":[краткий…]}` (свои + где участник, по updated_at desc) |
| POST | /api/playlists | `{"name","description"?,"shared"?:bool,"track_ids"?:[…]}` | краткий (+`invite` если shared) |
| GET | /api/playlists/{id}?sort=&order= | — | краткий + `"sort"` + `"tracks":[трек+item_id+added_by…]` (+`invite` для владельца общего); `sort`: `manual` (порядок плейлиста, по умолчанию) / `added` (когда добавлен в плейлист) / `title` / `artist` / `album` / `genre` / `year` / `duration` / `random` (+`seed`), `order`: `asc`/`desc` — см. APPS_API.md |
| POST | /api/playlists/{id}/update | `{"name"?,"description"?}` | краткий |
| POST | /api/playlists/{id}/share | `{"enabled":bool,"regenerate"?:bool}` (только владелец) | `{"shared":…, "invite": {...}|null}` |
| POST | /api/playlists/{id}/add | `{"track_ids":[…]}` или `{"album":{"a":..,"b":..}}` или `{"artist":"<folder>"}` | `{"added":n,"skipped":m,"count":…}` |
| POST | /api/playlists/{id}/remove | `{"item_ids":[…]}` | `{"removed":n,"count":…}` |
| POST | /api/playlists/{id}/move | `{"item_id":…, "to":index}` | `{"ok":true}` |
| POST | /api/playlists/{id}/delete | — (только владелец) | `{"ok":true}` |
| POST | /api/playlists/{id}/leave | — (участник) | `{"ok":true}` |
| POST | /api/playlists/{id}/kick | `{"login":…}` (только владелец) | краткий |
| POST | /api/playlists/{id}/save | — | `{"linked":n}` — недостающие треки → медиатека пользователя (хардлинк) |
| GET | /api/playlists/join?token=… | — | превью: `{"id","name","owner","count","covers","already":bool}` |
| POST | /api/playlists/join | `{"token":…}` | краткий |
| GET | /api/playlists/for-track?track_id=… | — | `{"items":[{"id","name","has":bool}]}` — для листа «Добавить в плейлист» |

`invite`: `{"token":"…","link":"https://t.me/<bot_username>?start=pl_<token>","app_link":"<STREAM_PUBLIC_URL>/app/#join=<token>"}`.
Имя бота — `getMe` при старте (кэшировать), без него `link` = null.
404 для чужих/несуществующих плейлистов (не 403 — не раскрывать существование). Мутации обновляют `updated_at`.

## Бот (`bot.py`)
- `/start pl_<token>` → превью плейлиста + кнопка WebApp «Открыть плейлист» (`/app/#join=<token>`) — вступление
  происходит в Mini App по кнопке «Присоединиться» (не молча по ссылке).
- `/playlists` → список плейлистов текстом + кнопка WebApp «Открыть плейлисты» (`/app/#playlists`).
- Обновить HELP: раздел про плейлисты.
- Jellyfin-зеркало (best effort, в фоне, с debounce ~10 с после изменений): для владельца и каждого участника
  плейлист с тем же именем в Jellyfin, только из треков, которые есть в его медиатеке (у Jellyfin изолированные
  библиотеки). Хранить id в kv `pl_jf:<playlist_id>:<login>`; использовать `jellyfin.replace_playlist`.
  Ошибки Jellyfin не должны ломать API.

## Mini App (`static/`)
- `player.js`: два режима на одном `<audio>` — `wave` (живой поток, как сейчас) и `queue` (файлы).
  Очередь: `playQueue(tracks, startIndex, {shuffle, source:{kind,id,title}})`, `next()`, `prev()` (если >3 с — в
  начало), `seek(sec)`, `toggleShuffle()`, `cycleRepeat()`, `addNext(track)`, `addToQueue(track)`, `removeAt(i)`,
  `moveItem(from,to)`. Автопереход по `ended`, предзагрузка следующего (`<link rel=preload>` или второй Audio с
  `preload=auto` за 15 с до конца). Media Session: metadata+artwork, `play/pause/previoustrack/nexttrack/seekto/
  seekbackward/seekforward`, `setPositionState`. Состояние очереди и позиция сохраняются в localStorage
  (try/catch) и восстанавливаются **на паузе** (без autoplay). Превью из поиска останавливает/ставит на паузу очередь,
  как сейчас волну. Подписанные `stream`-ссылки живут 12 ч: при восстановлении очереди из localStorage и при ошибке
  старта трека клиент обновляет ссылки через `GET /api/tracks?ids=1,2,3` (≤ 500 id) → `{"items":[трек…]}`
  (только доступные пользователю треки); недоступный трек пропускается.
- Мини-плеер (общий для волны и очереди): обложка, название/исполнитель, прогресс-линия, play/pause, next.
  Тап → полноэкранный «Сейчас играет» (M3E): крупная обложка с формой, цвет из обложки, волнистый прогресс со
  слайдером перемотки (доступный: role=slider, клавиатура), время, shuffle/prev/play/next/repeat, кнопки
  «В плейлист», «Очередь» (лист очереди: текущий, далее, перетаскивание/удаление), переход к исполнителю/альбому.
  Широкие экраны: «Сейчас играет» — в правой панели / боковом листе, не на весь экран.
- Треки в медиатеке, альбоме, исполнителе, плейлисте: тап по ряду = играть этот список с этого трека.
  Кнопки «Слушать» и «Перемешать» в шапках альбома/исполнителя/плейлиста/медиатеки. Меню ряда (⋮ или long-press):
  «Играть следующим», «В очередь», «Добавить в плейлист…», «К исполнителю», «К альбому», «Удалить из медиатеки».
  Текущий играющий трек подсвечен (эквалайзер-иконка) во всех списках.
- Плейлисты: сегмент/вкладка «Плейлисты» в медиатеке (сетка с мозаикой обложек, FAB/кнопка «Новый плейлист»),
  экран плейлиста (шапка-мозаика, имя, описание, участники-аватары, бейдж «Общий», Слушать/Перемешать, меню:
  переименовать, поделиться, участники, сохранить в медиатеку, удалить/выйти), режим правки (перетаскивание,
  удаление). Диалог создания: имя, «Общий плейлист» (switch). «Поделиться»: Telegram `openTelegramLink(
  "https://t.me/share/url?url=<link>&text=…")` + копировать ссылку. Экран вступления `#join=<token>`:
  превью + «Присоединиться». Лист «Добавить в плейлист»: список с отметками + «Новый плейлист».
- Состояния: загрузка (скелетоны), пусто («Создайте первый плейлист»), ошибка с повтором, нет доступа к плейлисту.

## Изменения бэкенда
Всё обратно совместимо с контрактом выше; уточнения:
- Коды ошибок (`{"error", "message"?}`): `400 bad_name / bad_description / bad_track_ids / bad_item_ids / bad_move /
  bad_enabled / bad_album / bad_artist / nothing_to_add / bad_ids / too_many / bad_order / bad_track_id`;
  `404 not_found` (чужой/нет плейлиста, недействительный токен приглашения, позиция для `move` не найдена);
  `404 not_member` (kick); `403 forbidden` — участник вызвал действие владельца (`share`, `delete`, `kick`);
  `409 limit` (200 плейлистов), `409 members_limit` (20 участников), `409 owner_cannot_leave`.
- `GET /api/tracks`: больше 500 id → `400 too_many`; нечисловой id → `400 bad_ids`; повторы схлопываются.
- `GET /api/library/play`: `order` по умолчанию `artist` (порядок папок исполнитель/альбом/файл).
- `POST /api/playlists/{id}/add`: можно добавлять любой доступный пользователю трек (медиатека **или любой** его
  плейлист, а не только этот же) — чтобы «Добавить в плейлист…» работало для трека из чужого общего плейлиста.
  `album`/`artist` — папки **своей** медиатеки. Если плейлист заполнен (5000), в ответе ещё `"full": true`
  (непоместившиеся считаются в `skipped`). Для несуществующего исполнителя/альбома — `{"added":0,…}`.
- `POST /api/playlists/{id}/update` разрешён и участникам (в таблице контракта он не помечен «только владелец»).
- `share {"enabled": false}`: участники остаются участниками, по старой ссылке вступить нельзя.
  `enabled: true` без `regenerate` сохраняет текущий токен.
- `move`: `to` — индекс в итоговом списке (0…len-1, обрезается); позиции дробные, при схлопывании зазора —
  перенумерация.
- Превью `GET /api/playlists/join`: обложки подписаны логином владельца (у приглашённого ещё нет доступа к трекам).
- `invite` есть в ответах `POST /api/playlists` (если `shared`), `GET /api/playlists/{id}` и `POST …/join` —
  только для владельца общего плейлиста.
- Файл общего кэша держат только медиатеки: трек, которого не осталось ни в одной медиатеке (удаление из медиатеки,
  из плейлиста, удаление плейлиста или аккаунта), удаляется с диска и пропадает из всех плейлистов.
- Jellyfin-зеркало: ≤ 500 треков; одноимённые ручные плейлисты не ищутся и не удаляются; id зеркал входят в
  список «своих» при очистке лишних «Моя Волна…».
- Краткий плейлист: `shared` = есть ссылка-приглашение **или** участники (совместный); новое поле
  `invite_enabled` = ссылка сейчас работает (`share_token` не NULL). Бейдж «Общий» — по `shared`,
  переключатель «Общий доступ» — по `invite_enabled`.
- `POST …/kick`: если ссылка была включена, токен меняется (исключённый не вернётся по старой ссылке);
  ответ — краткий + `invite` с новым токеном (для владельца).
- `POST …/save` → `{"linked": n, "missing": m, "failed": k}` (`missing` — файла нет в общем кэше,
  `failed` — ошибка связывания).
- id в запросах (`ids`, `track_ids`, `item_ids`, `item_id`, `track_id`): целые 0 < id < 2^62, иначе 400
  (в пути — 404). `move.to` обрезается в допустимый диапазон.
- `/api/stream`: `Content-Type: audio/mpeg` только для `.mp3`, для других форматов тип определяется по файлу.
- Новый `POST /api/download/link {"url"}` — ссылка (Spotify / YouTube / SoundCloud / Bandcamp / Яндекс…), как
  если бы её прислали боту → `{"queued", "title", "kind", "note": str|null, "playlist": {"id","name"}|null}`.
  Для ссылки на **плейлист** сразу создаётся плейлист бота (порядок — как в источнике, наполняется по мере
  загрузки). `note` — предупреждение для показа (например, Spotify без входа отдал только первые 100 треков).
  Ошибки: `400 bad_url`, `422 resolve_error` (с `message`), `404 nothing_to_download`, `502 resolve_failed`.
- Импорт файла (Tune My Music CSV/TXT) создаёт плейлист бота с именем файла (без расширения; «(2)», если занято),
  порядок — как в файле, первые 5000 треков. Обычный плейлист: его можно переименовать/удалить; удалённый
  заново не создаётся.

## Вопросы фронтенда
1. **Ключи папок у трека.** «К исполнителю» / «К альбому» из списков и «Сейчас играет» сейчас ищут исполнителя/альбом
   по названию в `/api/library/artists` и `/api/library/albums` (`_lib_item` не отдаёт папки). Если добавить в
   сериализацию трека `artist_key` и `album_key` (как `a`/`b` в `/api/library/album`), клиент возьмёт их сразу
   (поддержка уже есть). Для треков не из медиатеки — `null`, тогда клиент ищет исполнителя в каталоге.
2. `kick` / `share` клиент читает поля `invite`, `invite_enabled`, `shared`, `members` из ответа, если они есть;
   иначе оставляет прежние значения до следующего открытия плейлиста.
3. Очередь хранится в `localStorage` под ключом `pimusic.queue.v1:<login>` (до 3000 треков, со ссылками); при
   восстановлении старше 6 ч ссылки обновляются пачками по 500 через `/api/tracks`.

## Текст песни: найти заново (2026-10-27)
`POST /api/tracks/{id}/lyrics/refetch` (тело необязательно: `{"clear": true}`) — перезапросить текст трека по новым
правилам проверки; ответ — как у `GET /api/lyrics/{id}` плюс `status` (`updated` | `same` | `cleared` |
`not_found`). Подробности, ошибки и правила подбора — `APPS_API.md`, раздел «Тексты песен: перезапрос и проверка».
